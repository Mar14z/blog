Spatial Memory Engine

不是一个流水线，是一个中心 + 四条边。

真实结构里，记忆核心是唯一的枢纽：采集侧单向写入，查询侧四条 API 读出， 持久化是异步旁路而不是管道的一环。语义编码横跨两侧，是写入和查询共用的服务，不属于任何一边。

已实现 部分实现 未做 不可行
01

模块结构

虚线框是尚未成型的模块。三处容易画错的地方：语义编码不是流水线的一步，它同时服务写入和查询； 时间查询不查内存，它直接读 SQLite；持久化是旁路，写队列异步落盘，重启时再反灌回内存。

02

单帧数据流

这是执行视角，不是模块依赖。采集之后三条支路并行：检测出框、定位出坐标、视觉塔出特征， 前两条汇合成 Observation，第三条单独走特征通道。③ 3D 定位是整条链路唯一的技术空白。

03

ROS2 节点划分

按生命周期和故障域拆，不按算法步骤拆。引擎是单写者、无锁，只能有一个进程持有它； 视觉塔和文本塔分进程，避免 10Hz 的写入被按需触发的查询阻塞。

接口类型方向说明
/camera/rgb · /camera/depthtopic · SensorDatasensor → perceptionbest effort，丢帧可接受
/sm/observationstopic · Reliable(10)perception → memory观测直接带 512 维特征，省一次 RPC
/sm/query_radiusserviceclient → memory中心 + 半径 + 类别
/sm/query_textserviceclient → memory文本塔 9ms + 余弦检索
/sm/query_historyserviceclient → memory读 SQLite，不读内存索引
/pincher/graspactionbridge → 夹爪目标位姿 + 状态回报

并发规则：sm_memory 必须用 SingleThreadedExecutor，否则查询回调会和写入回调同时遍历无锁的实体池； sweep 走 1Hz 定时器，而不是每 1024 次写入触发。

同一个物体，从像素到磁盘经过五种表示。体积逐级收缩，这是能跑在 8 TOPS 边缘设备上的原因。
